## 装饰体系：昵称特效色 + 官方背景库

- 背景：用户此前已有「个人主页背景」（自传图）与「主页头图」。本次新增两类装饰，均按贡献分**等级门槛**开放、**不扣贡献分**。头像框被用户否掉（头像是方的，不适合框）。
- 核心口径：贡献分是荣誉层（只增不减），**扣它 = 掉级**，会连带把已达标的装饰一起打回锁定 → 装饰一律只做门槛、不做消耗。想要「消费感」就走 PIX（资产层，有 CoinLedger）。
- 唯一事实来源 `src/lib/decorations.ts`：8 款昵称色 + 8 款官方背景预设，**每款的解锁等级写死在清单里**，不进后台配置。理由：昵称色值必须是 Tailwind 字面量类名、官方背景是随仓库发布的静态资源，后台都无法新增，做成配置只会得到「配置里有、源码里没有」的假选项。后台只留两个总开关（`incentive.decoration.nicknameEnabled` / `bgPresetEnabled`）。
- 昵称色必须维护**两套色值**：`--nick-*`（跟随明暗主题，用于浅底页面）与 `--nick-*-bright`（固定亮阶，用于资源卡黑条、首页大图）。两套取值区间互斥——浅底要相对亮度 ≤0.17、黑底要 ≥0.21，一个值不可能两边都达标。
- 判定策略刻意分叉：背景预设走**实时**等级判定（与存量 `profileBgUnlocked` 同纪律）；昵称色只在**设置时**判定，渲染只看「有没有值 + 功能开关」——它出现在几十个渲染点，逐点回查作者等级不现实，且贡献分只增不减、装饰也不扣分。
- 数据层：`User.nameColor` / `User.profileBgPreset`（迁移 `0012_decorations.sql`）。预设与自传图**互斥**，写侧双向清理（选预设清 key、传图清 preset）。
- 后台 `IncentiveManager.tsx` 的 `GROUPS` 常量必须包含新分组，否则 `buildPayload` 不带它、保存任意其他设置时会被 zod default **静默重置**。
- 素材：`public/bg/*.svg` 8 款程序化生成的像素图案（SVG pattern 平铺，1920×1200，单张 1–2KB），风格与站点像素语言一致。
- 昵称色已接入：个人主页 h1、ResourceCard、ResourceRow、评论与楼中楼回复、首页 hero（大图/卡片/list 三种形态）、侧栏 mini 行卡与卡片。**未接入**：UserHoverCard 内部、粉丝关注列表、侧栏「最近评论」、通知列表、后台表格（这些位置要额外回查等级或补 select，留作后续）。
- 验证：`npx tsc --noEmit` 干净；`npm run lint` 0 error / 6 warning（全部为存量：prisma/seed-*.ts、admin/media、PublishForm，无新增）。未跑 build、未起 dev server、未做运行时截图。
