# 2026-09-25

## 修复 S3 上传对象 Content-Type 缺失（图片直链变下载）

- 根因：`src/lib/storage/s3.ts` 的 `put()` 只发 Bucket/Key/Body/ACL，**没有 ContentType**；S3 不按扩展名猜类型，对象一律落成 `binary/octet-stream`，浏览器直链访问即下载。
- 修法：
  - 新增 `src/lib/storage/mime.ts`：扩展名→MIME 表 + `mimeFromExt` / `mimeFromKey` / `resolveContentType`。`resolveContentType` 优先用调用方声明值，但做形状校验 + 危险类型黑名单（text/html、image/svg+xml、js、xml），命中则回退 key 扩展名——防止把存储域名变成 XSS 托管点。表中**故意不收录** svg/html/js/xml。
  - `StorageDriver.put(key, buf, contentType?)` 增加可选第三参（向后兼容），`saveFile` 透传；s3/chevereto 驱动统一走 `resolveContentType`，chevereto 里原来那份重复的 MIME 表已删除。
  - 调用点补真实 MIME：`media/process.ts`（原图 mime、大图/缩略图 `outputMime(cfg.format)`）、`actions/settings.ts`（头像/横幅/主页背景）、`actions/social.ts`（评论附图）、`actions/admin-media.ts`、`api/upload/attachment/route.ts`（用客户端 `file.type`，由驱动侧过滤）。
  - 存量对象修复脚本 `prisma/fix-s3-content-type.ts`（npm script: `s3:fix-content-type`）：CopyObject + `MetadataDirective=REPLACE` 原地重写元数据，默认预演、`--apply` 生效；CopyObject 不继承 ACL，脚本按驱动口径补回 `public-read`，遇 `AccessControlListNotSupported` 自动去 ACL 重试。
- 验证：`npx tsc --noEmit` 通过；`npm run lint` 0 error（6 个 warning 全是既有）；`npm run build` 通过（需 `CODEBUDDY_SAFE_DELETE_ENABLED=0`，否则沙箱 safe-delete 守卫会拦下 Next 清理 `.next/turbopack`）。MIME 解析逻辑用临时脚本跑过 13 组用例。
- 未做：OneDrive 走 Graph（`uploadDriveFile` 固定 `application/octet-stream`），其 MIME 由 SharePoint 按文件名后缀决定，不受此 bug 影响，未改动。
