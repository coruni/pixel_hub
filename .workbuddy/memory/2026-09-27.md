# 2026-09-27

## 草稿保存完整性修复（/upload 向导 + 后台改稿页）

用户反馈「保存草稿后游戏类型的游戏信息没保存完整」，排查出四处同类问题，全部按
「草稿能存什么，恢复时就必须原样填回」的口径修掉：

1. `GameSection`（wizard-sections.tsx）的**语言 / 平台**输入框没有 `defaultValue`，只接了
   `downloads`。草稿恢复后这两栏永远是空的 → 加 `initial={{ lang, platforms }}`，
   `UploadWizard` 与 `ResourceEditForm` 两个调用点都传。
2. GAME **下载源的 kind/size** 恢复时被丢弃（`InitialDownload` 只有 name/url，kind 硬编码
   "link"）→ 站内附件（`/od/…`）会被还原成「网盘外链」，详情页标识与下载行为都错。
   `InitialDownload` 补 kind/size，两个调用点一并透传。
3. **发布选项三个勾选**（nsfw / loginRequired / allowComments）在 `UploadWizard` 里写死
   `checkedOf={(name) => name === "allowComments"}` → 恢复草稿后 nsfw/loginRequired 永远未勾选、
   allowComments 永远勾选，下一次自动保存就把用户的选择静默写坏 → 改为读草稿快照。
4. **切类型会清空已填内容**：类型分节是非受控输入，切走即卸载重挂载，而回填只认初次传入的
   `initialDraft`（新建场景下为 null）→ 切回后整段空白，紧接着自动保存把空值写进草稿。
   引入 `draftSnap`（每次保存成功后同步最新落库快照）供分节重新挂载时回填。

顺带：`lib/draft.ts` 抽出 `draftDownloadsOf()`（GAME/IMAGE/ARTICLE 共用一份清单解析，
`UploadWizard` 里那份重复实现删掉）；`draftReadyHint` 的 GAME 判断从已废弃的
`externalUrl` 改为 downloads 里是否有 url（否则永远提示「还差下载外链」）；
`lib/actions/resource.ts` 的 `allowComments: fd.get("allowComments") !== "off"` 恒为 true
（复选框未勾选时 FormData 里没有该 key）→ 改判 `=== "on"`，与 `_resource-edit.ts` 的 `on()` 一致。

## 下载来源标识：站内路径一律算「附件」

同一批走 OneDrive 的下载源出现「一个显示外链、一个显示附件」。根因是 `kind` 只是写入时记录
的字段，历史数据里有脏值。改为**按 URL 重判**：`lib/meta.ts` 新增 `downloadKindOf()`
（URL 以 `/` 开头 → file），并在 `articleItemSchema` / `imageDownloadSchema` 上挂
`.transform()`——`parseMeta`（读取）与各 action（写入）都过这一层，存量数据不用改库就治好。
`/api/dl` 本身支持 `/od/…`（302 到 Graph 预鉴权链接），所以归类为 file 的下载路径是通的。

## 其他

- 资源详情页 `TypeInfoCard` 的「类型」由文字改为图标；类型图标表收敛到新文件
  `src/components/resource/type-icon.tsx`（`TYPE_ICON` + `TYPE_BADGE_TONE` + `TypeIcon`），

  `.group` 就丢了 `:hover`）；弹层常驻 DOM 并靠 `visibility` 显隐（`:hover` 依赖命中测试，
  不可命中就断链）；`transition-[opacity,visibility] duration-150` 提供 150ms 移入缓冲
  （visibility 是离散可过渡属性，过渡中插值结果仍是 visible）。
  随之删掉已无引用的 `src/lib/hooks/use-hover-delay.ts` 及其 barrel 导出。

## 资源详情页标签胶囊配色

标签原先与元数据 chips 同色（`bg-neutral-100 text-neutral-600`），读者分不出「可点的标签」
和「只读的属性」。改为品牌淡橙底：`bg-brand-100 text-brand-700`，hover `bg-brand-200
text-brand-800`。三处渲染（parts.tsx 的 MetaBlock、DetailArticle 文末、DetailPost 信息条）
原本各抄一份 class，收敛到新文件 `src/components/resource/TagChip.tsx`（导出 `TagChip` 与
`TAG_CHIP_CLASS`，`className` 仅用于对齐各调用点字号，DetailPost 传 `text-[11px] font-medium`
对齐它的 chipBase）。

配色约束（写死在注释里）：hover 必须同时换到 `text-brand-800` —— brand-700 压 brand-200
在亮色下只有 4.11:1，不满足 4.5:1；brand-800 是 5.44:1。亮色 `bg-brand-100 #faece3`
对 `surface #fffdf9` 仍可辨；暗色 brand-100 变 `#33281e`、brand-700 变 `#ecb39a`（7.85:1）。
**不要用 `bg-brand-50`**：亮色下 `#fdf5f0` 与 surface 几乎同色，等于没有底色。
