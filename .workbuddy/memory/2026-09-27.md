   引入 `draftSnap`（每次保存成功后同步最新落库快照）供分节重新挂载时回填。

顺带：`lib/draft.ts` 抽出 `draftDownloadsOf()`（GAME/IMAGE/ARTICLE 共用一份清单解析，

### 核心洞察：断点互斥的层 + `:has()` 会串槽

两槽是靠 Tailwind 的 `hidden sm:block` / `sm:hidden` 互斥显示的，而 **`:has()` 只看「元素在不在
DOM 里」、不看它是不是 display:none**。原来那条不分断点的优先级规则

```css
body:has([data-profile-bg-owner]) [data-profile-bg-global] { display: none }
```

在新结构下会串槽：作者只设了**桌面端**那张图时，移动端的 owner 元素照样在 DOM 里（只是被
`sm:hidden` 藏着）→ 移动端访客自己的全局背景被无理由隐掉，而它本该照常显示。

改成按断点成对，并把属性名也带上槽位后缀（`data-profile-bg-owner-pc` / `-mobile`、
`data-profile-bg-global-pc` / `-mobile`）：

```css
@media (min-width: 40rem) { body:has([data-profile-bg-owner-pc]) [data-profile-bg-global-pc] { display: none } }
@media (width < 40rem)    { body:has([data-profile-bg-owner-mobile]) [data-profile-bg-global-mobile] { display: none } }
```

`width < 40rem` 与 Tailwind v4 的 `sm`（40rem）严格互补，不留空隙也不重叠。要点是让
「owner 存在」与「owner 此刻可见」在**同一个断点里**成立。
