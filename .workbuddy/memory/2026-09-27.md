### 核心洞察：断点互斥的层 + `:has()` 会串槽

两槽是靠 Tailwind 的 `hidden sm:block` / `sm:hidden` 互斥显示的，而 **`:has()` 只看「元素在不在
DOM 里」、不看它是不是 display:none**。原来那条不分断点的优先级规则

```css
body:has([data-profile-bg-owner]) [data-profile-bg-global] { display: none }
```

在新结构下会串槽：作者只设了**桌面端**那张图时，移动端的 owner 元素照样在 DOM 里（只是被
`sm:hidden` 藏着）→ 移动端访客自己的全局背景被无理由隐掉，而它本该照常显示。

改成按断点成对，并把属性名也带上槽位后缀（`data-profile-bg-owner-pc` / `-mobile`、
`data-profile-bg-global-pc` / `-mobile`）：

```css
@media (min-width: 40rem) { body:has([data-profile-bg-owner-pc]) [data-profile-bg-global-pc] { display: none } }
@media (width < 40rem)    { body:has([data-profile-bg-owner-mobile]) [data-profile-bg-global-mobile] { display: none } }
```

`width < 40rem` 与 Tailwind v4 的 `sm`（40rem）严格互补，不留空隙也不重叠。要点是让
「owner 存在」与「owner 此刻可见」在**同一个断点里**成立。

## 事故：发布资源失败 —— 事务内 catch 唯一键冲突把事务打成 aborted

用户贴线上容器日志。**表象**是 `prisma.media.updateMany()` 抛
`PrismaClientUnknownRequestError` + `code: 25P02 current transaction is aborted, commands ignored
until end of transaction block`，前面几行还夹着
`Invalid prisma.tagOnResource.create() invocation: Unique constraint failed on (resourceId,tagId)`。

**根因不在 media，在上一句的 tagOnResource.create。** Postgres 的交互式事务是「一旦有语句报错，
整个事务立刻 aborted」，之后每条语句都返回 25P02 —— **与 JS 层有没有 catch 无关**。
`tagOnResource.create().catch(() => null)`（注释写着「并发去重」）只吞掉了 JS 错误，事务在服务端
已经死了，于是紧接着的媒体认领必然炸，并把真正的根因盖掉。同文件里
`tx.tag.create().catch(() => tx.tag.findUnique(...))` 是同一个错误的另一处。

**为什么会有重复键**：`names` 只按名字去重，但两个不同输入名可以解析到**同一个 Tag 行** ——
命中链是 `findUnique(slug) ?? findUnique(name) ?? create`，用户同时填「云」和「yun」时
拼音 slug 都是 `yun`，第二条会经 slug 命中第一条刚建的标签 → 同一个 tagId 关联两次。
（`_resource-edit.ts` 里改名新建标签也有同款：`tx.tag.create` 撞 slug 唯一键 → catch → 全事务死。）

**修法**：新增 `src/lib/actions/_tags.ts`
- `findOrCreateTag(tx, name, slug)`：先按 name、再按 slug 双查（只查 name 会漏掉 slug 撞车），
  未命中用 `tag.createMany({ skipDuplicates: true })`（PG: `ON CONFLICT DO NOTHING`，
  冲突不报错、不中断事务）再回查。
- `linkTag(tx, resourceId, tagId)`：同样走 `createMany({ skipDuplicates: true })`，
  用返回的 `count > 0` 决定是否给 `Tag.count` 加一。
- 两个调用点（`resource.ts` 的 `createResourceAction`、`_resource-edit.ts` 的 `applyResourceEdit`）
  都改成「`linkedIds` Set 按 tagId 去重 + 上面两个 helper」，删掉全部 `.catch()` 兜底。

验证：`tsc --noEmit` 干净、`eslint` 3 个文件 0 error 0 warning。未做运行时实测。

**同一份日志里的另一条（与本 bug 无关）**：`failed to get redirect response TypeError: fetch failed`
→ `ERR_SSL_PACKET_LENGTH_TOO_LONG`。这是出站 HTTPS 被中间人/代理干扰（本机 Clash TUN 那类），
发生在 `autoSlugBase` 的翻译请求上；该函数有拼音兜底，不影响发布。

### 追认口径：名字不同但翻译出的 slug 相同 = 同一个标签，直接合并

用户：「新tag名字不一样 但是翻译的slug一样就直接合并。」

- **发布 / 改稿路径本来就符合**：`findOrCreateTag` 的命中链是「按 name 查 → 按 slug 查 → 才新建」，
  slug 撞上别人就复用那一行，既不报错也不新增词条（这正是上一节修掉重复关联键的底气）。
  优先级是 **name 优先、slug 兜底**：作者手填的名字若能对上，就按名字走；对不上再按 slug 归并，

- **管理后台的改名路径原本不符合**，已改：`renameTagAction` 原先在「slug 被别的标签占用」时

## 字幕 / 歌词（2026-09-27）

用户：「补充 音频挂载歌词 vtt lrc srt？还有什么？ 顺便把视频挂载字幕也补了」。

**格式清单**：支持 vtt / srt / lrc / ass+ssa（只取时间与文本，样式特效全丢）/ txt（无时间轴，
只作静态文本）。不做：smi(SAMI)、ttml/dfxp（同类且极少用）、sub+idx（图形字幕，要 OCR）。

**核心决策：字幕文本内联进 `meta.captions[].text`，不存地址、不走上传通道。**三条理由：
1. `<track>` 只吃 WebVTT，srt/lrc 反正要自己解析，走不上「给 src 让浏览器去拉」那条路；
2. 站内云盘引用（`/od/…`）会 302 到 Graph 预鉴权链接，**那个响应不带 CORS 头**，客户端 fetch 必失败
   —— 内联完全绕开，也不必为此新开一个「本站转发字节」的代理路由（还要自带鉴权/限流/SSRF 防护）；
3. 字幕很小（一部电影 20–80KB），随详情页一次带下来比多一次往返划算；`feedSelect` 不取 meta，
   列表页不会被拖胖。
代价是 meta 变大，所以给了硬上限（单份 `AV_CAPTION_TEXT_MAX = 160_000` 字符、最多 6 条）。

- **`src/lib/captions.ts` 是字幕的唯一事实来源**：格式表、上限、格式嗅探、五种解析器、二分找当前行、
  表单 JSON 序列化全在里面。单向依赖 `meta.ts → captions.ts`（meta 引格式枚举与上限），
  **不能反过来**，否则循环。
- 解析实现要点（都踩过）：
  - **时间戳按小数位数定标**：1 位=十分秒、2 位=厘秒（ASS 的 `.cc`）、3 位=毫秒。
    统一的 `parseTimestamp` 只按冒号段数（2 段 = m:s，3 段 = h:m:s）分派，五种格式共用一个函数。
  - **`end` 只收紧、不拉长**：srt 两条 cue 之间的空档是「字幕消失」，拉长会让它一直挂着；
    而 lrc 给的占位 end 必然超过下一条 start，正好被同一规则收紧成「唱到下一句」。
  - ASS 的字段位置**按同段 `Format:` 行动态定位**（不同工具顺序不一致），Text 用 slice 而非下标取
    （它是最后一个字段且内部可以含逗号）。
  - LRC 一行可挂多个 `[mm:ss.xx]`（副歌复用）；`[offset:±ms]` 生效在**每一行**上（我第一版测试
    期望就写错了这个）；增强型 lrc 的行内 `<mm:ss.xx>` 只剥不解析（否则和行首标签重复计一遍）。
  - `parseCaption` 在「整份解析不出时间轴」时回落静态文本（把 txt 当 srt 传进来的情形）。
- **渲染全自绘，不用 `<track>`**：原生 cue 的样式活在 UA shadow 里，改不动，与「直角 + 像素字体」
  冲突。视频 = 压在画面底部的叠层（`bottom-14` 让开底部控件行，`pointer-events-none` 不挡画面点击）；
  音频 = 卡片内滚动歌词板（当前行高亮、点行 `currentTime = cue.start` 跳转）。
- **歌词板自动滚动手算 `scrollTop`，不用 `scrollIntoView`** —— 后者会把整个页面一起滚下去，
  用户正看着歌词页面自己往上跳。动效跟随 `prefers-reduced-motion`。
- 落位：**视频的字幕开关与分P 列表开关并排在右上角浮层**（底下控件行 320px 排满，塞不进）；
  音频放控件行（那行本来就 `flex-wrap`）。**开关既切显隐也切歌词板的存亡**，不另做折叠。
- 顺手修 `AvListToggle`：它用 `SIZE[size]`（写死 `w-9`/`w-11`）却要塞图标 + 「3/8」文本，
  固定宽度让文本溢出容器、与相邻按钮重叠 → 改用新导出 `AV_BTN_HEIGHT`（只取高度）+ `px-1.5`。
  新抽出 `av-btn.tsx` 放按钮原语（`AV_TONE` / `AV_BTN` / `AV_BTN_SIZE` / `AV_BTN_HEIGHT`），
  av-playlist 与 av-captions 平级共引，不让其中一个 import 另一个。
- `parseMeta` 的降级链从两级变三级：整块 → 丢 captions → 再丢 tracks → 兜底。字幕是最容易被卡住的
  那项（长文本），所以先丢它、保住分P 与主来源。
- 草稿 `avCaptions` 上限设 **1_200_000**（6×160K 再留 JSON 转义膨胀余量）：`draftPayloadSchema`
  一旦 safeParse 失败，`parseDraftPayload` 会把**整条草稿**回落成空，作者填的其它字段一起陪葬 ——
  宁可放宽也不能收紧。
- 字幕**不走上传通道**（不落存储、不产生孤儿文件、不撞云盘 CORS），向导只有两条入口：
  「选择文件读文本」（`file.text()`，按后缀/内容嗅探定格式）与「粘贴文本」。超长**硬拒，不截断**
  —— 截断产出的是时间轴错位的坏字幕，比没有更难查。
- 嵌入页（iframe）的字幕由来源站点控制，站内挂的这份不生效 → 详情页给出明确提示，不让作者以为挂丢了。
- 验证：tsx 探针 `prisma/_capcheck.ts` **64 项全 PASS**（五种格式各自的关键行为 + 格式嗅探 +
  序列化 + activeCueIndex 边界 + parseMeta 三级降级链 + 6/7 条上限），postcss 实编 16 项类产物
  全 PASS，两个探针已删；`tsc --noEmit` 干净、`eslint` 0 error（6 条存量 warning）。**未做浏览器实测**。

   effect 就会重跑 → 反复 `panelRef.focus()` 抢焦点。解法：`useCallback(() => {...}, [])`。

**验证**：`tsc --noEmit` 干净、`eslint src/components/upload src/lib` 0 error。
Tailwind 类产出用临时探针 `prisma/_twcheck.mjs` 实编 `globals.css` 核对
（`bg-panel` / `max-w-md` / `p-1.5` / `-right-0.5` / `h-1.5` / `bg-stone-900\/40` 等全部命中），跑完即删。
**探针写法**：类名从 `process.argv` 传入、文件内不留字面量 —— 否则 Tailwind 扫描源码时会把探针自己
当成调用点，检查永远「通过」。另外 Tailwind 产物里类名中的 `.` 转义成 `\.`（`.p-1\.5`），
按 `.p-1.5` 去 `includes` 会假失败。

## 外观：新增「简洁模式」（访客降噪开关）

需求：访客看不惯别人设的背景图（遮罩形状由作者定，部分组合下正文被压得看不清）时，一键把

## 抽屉内补投放区（修「抽屉里的怎么不能拖拽」）

**根因**：抽屉打开后行上的 `useFileDrop` 因 `disabled: uploading || open` 关着，而抽屉自身没有投放区
→ 打开抽屉后拖拽完全无反应（抽屉是 `fixed`，但 DOM 上仍在那个 `<li>` 子树里）。

**第一版方案被自己否决（值得记）**：把整个 `<aside>` 做成投放区，再给内层字幕区加 `stopPropagation`。
`stopPropagation` 只挡得住「同一文件被两层各接一次」，**挡不住计数器错乱** —— 外层已 `depth=1` 时指针
移进内层，外层再也收不到 `dragleave`（`drop` 也被截断）→ 高亮永久卡死，拖出去松手都不复位。
所以撤销 `useFileDrop` 上的 `stopPropagation` 开关（连 `cut()` helper 一起），改为在文件头写清
「投放区不要嵌套」。

**最终修法：抽屉内两个投放区互为兄弟。**
- `av-item-drawer.tsx`：投放区只包「标题 + 地址」这个内层包块（`flex-1 overflow-y-auto p-4` 里的第一个
  子 div），高亮 `bg-brand-50 ring-2 ring-inset ring-brand-400`；字幕区留在该包块**外面**，与它同为
  `p-4` 的直接子元素。
- `caption-field.tsx`：投放区从空态虚线框**上移到最外层根 div**（整块字段都是投放区，已挂载时拖入
  即替换），高亮 `border-brand-500 bg-brand-50`；空态虚线框不再挂 `dropProps`。
- 两边都按后缀白名单过滤（媒体区 `avExtsFor(avKind)`、字幕区 `captionFormatOfName`），拖错区给
  针对性提示：字幕文件拖到媒体区 → 引导去字幕区；媒体拖到字幕区 → `looksMedia()` 拒绝（判据取
  「确定是媒体」而非「确定是文本」，后者会在 `.srt` / `.lrc` 上误报）。
- 拖拽时 hint 文案会从两行变一行 → 给地址 hint 的 `span` 加 `min-h-8` 兜住，否则内容跳动会让指针
  相对位置变化、引发 enter/leave 抖动。

**验证**：`tsc --noEmit` 干净、`npm run lint` 0 error（2 个存量 warning）；postcss 实编确认
`min-h-8` / `ring-inset` / `ring-brand-400` / `ring-2` / `bg-brand-50` / `text-brand-700` 均产出，
探针已删。未做运行时验收。
