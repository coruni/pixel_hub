## 追加：图片「首开失败、刷新才好」—— ERR_CONNECTION_RESET

**报障（用户问诊确认）**：线上容器；`net::ERR_CONNECTION_RESET`；**全站所有图**（含封面/头像）；
所有资源详情页都一样；每次打开页面都这样，手动刷新一次即正常。

**定性**：RST = TCP 连接被对端掐断，不是 404 / 路径错 / URL 错。已排除：详情页无缓存配置、每次动态渲染；
生产库 `storageDriver=local`（图片是 `/uploads/...` 同源路径）；无预签名 URL。浏览器**不会自动重发**
被 RST 的请求 → 用户看到的就是「裂图 + 必须刷新」。

**本次落地两层**：
1. `server.js`：`keepAliveTimeout = 5min` + `headersTimeout = +1s`。Node 默认只有 5s，而前置代理通常把
   到源站的连接留 60s 以上 → 源站先关、代理不知情、下一个请求发到已关闭 socket → RST。把源站超时调到
   比代理长，让**代理先关**，从根上消掉竞态。优雅退出补 `closeIdleConnections()`（否则 `close()` 每次
   都要等满 3s 兜底）。**改的是 server.js → 线上必须重建镜像。**
2. `src/components/layout/ImageRetry.tsx`（新，挂 root layout，不渲染 DOM）：全站 `<img>` 兜底重试。
   - 捕获阶段监听 `error`（资源错误不冒泡但会经过 window），最多 2 次，计数记在 `data-img-retry`；
   - 站内相对地址重发带 `?imgretry=N`（换连接 + 绕过可能被 immutable 缓存的失败响应）；外链/带签名
     绝对地址原样重发不动 query（`retrySrc` 用 URL API，覆盖旧参数不会越叠越长）；
   - **挂载时补扫 `img.complete && naturalWidth === 0`**：RST 几乎立刻返回，首屏图片的失败常在
     hydration 之前，只挂监听器会漏掉整批 —— 那正是「首屏全裂」的形态；
   - 不覆盖 CSS `background-image`（拿不到 error 事件），组件注释已写明。

**验证**：`tsc --noEmit` 干净；`eslint .` 0 error（2 条既有 warning 未新增，在 `admin/media/page.tsx`
与 `PublishForm.tsx`）；`node --check server.js` 通过；`retrySrc` 用 7 组用例实跑确认（含已有 query /
hash / 外链 / data:）。按要求未跑 build / dev，线上行为未运行时验收。

**留给用户排查（我访问不到部署主机）**：RST 还有另两种可能，代码侧改不掉 ——
① 容器进程被杀（OOM 或未捕获异常）：SIGKILL 会把在途 socket 一起 RST → 看 `docker logs`、
`docker inspect --format '{{.RestartCount}}'`、退出码 137；
② 前置代理自己重置（上游连接池 / 并发上限）→ 看代理错误日志，并把代理的上游 keepalive 调到比源站短。
