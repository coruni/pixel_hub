## 结算算式答疑：用户给的 `50*50/50*0.1` 不对（实测复算）
- 用真实 `allocate()` 跑探针（`prisma/_settle-math.ts`，已删）复算用户场景，结论：
  - **单位混了三层**：收入 100 是**元** → 池子要 ×100 变**分**（50% 时 = 5000 分，不是 50）；贡献分是**权重**（只进「你的分 ÷ 全站总分」这个比例）；`0.1` 不存在 —— `perYuan=100` 的换算是「1 元 = 100 PIX / 1 分钱 = 1 PIX」，作用在**金额**上，不乘在分数比例上。
  - 用户原式算出来是 **5**（左到右：2500/50×0.1），实际取决于 Σscore，且受两道闸门与封顶钳制。

## 编辑器为什么不能「直接写 [资金池](/fund)」（诊断，无代码改动）

- 问：编辑器里直接敲 `[资金池](/fund)` 行不行？答：**不行**，敲出来的会变成字面量文本。
- 两个原因叠加（都实测过）：
  1. `@milkdown/preset-commonmark` 只有 **图片** 输入规则（`insertImageInputRule`，`![alt](url)`），**没有任何 link 输入规则**，也没有 `Mod-k`；link 只能经 Crepe 工具栏的 `toggleLinkCommand`（`functionGroup` / `insertGroup` 各有一个 "link" 项）或粘贴产生。所以敲进去的 `[资金池](/fund)` 始终是 text 节点。
  2. 存盘时 text 节点走 `mdast-util-to-markdown`（remark-stringify 内核）的默认转义：`[`→`\[`、`(`→`\(`。实测 `toMarkdown(text("[资金池](/fund)"))` = `"\\[资金池]\\(/fund)\n"`。入库的是 `\[资金池]\(/fund)`，前台 react-markdown 按字面量渲染方括号。
- 渲染端本身没问题：`Markdown.tsx` 对 `href.startsWith("/")` 一律走 `next/link`。SSR 契约 9 条全绿（`[资金池](/fund)`→`<a href="/fund">`、多链接 + `#hash`、外链 `target=_blank`、转义产物不产链接、去掉反斜杠的**反证**如期变链接、字面方括号老内容不受影响）。
- 可用的两条路（都不需要改代码）：
  - 选中文字 → 工具栏「链接」→ 填 `/fund`。`sanitizeLinkHref` 对无 scheme 的串原样放行（`if (!scheme) return trimmed`），相对路径不会被加 `https://`。
  - **粘贴**纯文本 markdown：`@milkdown/plugin-clipboard` 的 `handlePaste` 在 `html.length === 0` 时走 `parserCtx` 解析，`[资金池](/fund)` 会变成真链接。
- 刻意不做的事：**不在渲染端把 `\[x]\(y)` 还原成链接** —— 内容里真正想显示字面方括号的地方会被一起改掉。
- 探针（`prisma/_linkcheck*.tsx` + `_linkstub/`，next/link 打桩）跑完已删。

## 修：后台「主页背景解锁等级」保存后弹回原值（我引入的 bug）

- **根因**：`IncentiveManager.tsx` 是**双份草稿** —— 数值叶子以 `text`（字符串）为准，非数值以 `draft.groups` 为准；
  `buildPayload()` 先铺 `groups`，最后再用 `text` **覆盖**。我的新下拉用 `setGroup("profile", { bgMinLevel: n })` 写进了 `groups`，
  而 `text["profile.bgMinLevel"]` 还是进页面时那份旧值 → 保存时被旧值盖回去。
  **保存其实返回成功，只是存的是旧值**；`useAction` 成功时**不打 toast、只 router.refresh()**，
  于是用户看到的就是「点保存 → 值弹回原样」=「保存失败」。
- **改法**：改用 `{...num("profile.bgMinLevel")}`（与 `ranking.limit`／`download.retainMonths` 等 20+ 行同款）。
  **铁律：本页数值叶子只能走 `num()`，`setGroup` 只用于布尔/字符串/数组。**
- **反证**：探针逐字抄 `toDraft`/`buildPayload` 跑两条路径 —— 旧写法落库值 = 2（复现），新写法 = 3；
  另加 4 条源码锚点（`...num("profile.bgMinLevel")` 在、`setGroup("profile"` 不在、抄写前提仍在）确认探针抄的是当前实现。11/11 通过。
- 顺手把三处「PC / 移动端各一张」过时文案改成「仅桌面端」：`UploadLimitsManager` 的 hint、`points-config` 的注释、`actions/uploads.ts` 的类型注释。
- 另记一条**尚未处理**的静默失败：server action **抛错**时 `useAction` 既不打 toast 也不 refresh（`await fn()` 外面没有 try/catch，
  与「返回 ok:false」是两条路）→ 数据库抖动会表现为「点保存毫无反应」。本次 dev log 里确实有
  `Can't reach database server` + `[settle:auto] 调度异常`（23:27）。本次故障不是它，但值得补一个 catch + toast。

## 主页背景：补上推荐规格（16:10）

- 用户问「推荐是什么规格？」。推导两块：① 遮罩**完全透明区间是 [24%, 76%]** ⇒ 中间 52% 的画幅在页面上看不见；
  ② `bg-cover` 只在图纸**比视口宽**时按高度贴满 → **左右被裁**（正好切在可见带上，最坏情况），
  图纸比视口窄/高时才只裁上下。
- 结论 **16:10（≥ 1920×1200，长边 2560 更清晰）**：16:10 屏零裁切、16:9 屏只裁上下 10%、21:9 屏裁上下 33%，
  左右全程完整；而常见的 16:9 图放到 16:10 屏会裁掉两侧约 5%，恰好落在可见带上。
- 落到两处文案：`ProfileBgForm.tsx`（「建议横图」→ 具体规格 + 主体放左右两侧）、`UploadLimitsManager.tsx` 的后台 hint。
  几何推导已记入 `REFERENCE.md` 的「个人主页背景」小节。
