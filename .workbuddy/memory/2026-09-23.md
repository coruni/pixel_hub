# 2026-09-23

## Redis 缓存后端支持密码
- `cache-handler.js`：新增 `splitCredentials()`，把 `redis://user:pass@host` 的 userinfo 摘出来，
  再以 `username`/`password` 选项传给 `createClient`。原因：`@redis/client` 的 `parseOptions`
  是 `Object.assign(options, parsedUrl)`，URL 里的凭据会**覆盖**显式 password，两边都配时谁生效不可控。
  优先级固定：环境变量 `REDIS_USERNAME`/`REDIS_PASSWORD` > URL 内嵌。URL 凭据 percent-decode。
- `next.config.ts`、`cache-plan.md` 同步补充凭据配置说明（内嵌 vs 独立环境变量，TLS 用 `rediss://`）。
- 启用门控仍是 `REDIS_URL`，未变。

## Docker 启动崩溃 Cannot find module '/app/.next/cache-handler.js'
- 根因：Next 内部**两处**解析 `cacheHandler` 且基准不同——构建/导出期 `createIncrementalCache`
  用 `dir`（项目根），运行时 `next-server.js` 用 `this.distDir`（`.next`）。相对路径 `./cache-handler.js`
  导致构建期命中、运行时找 `.next` 下，直接 ERR_MODULE_NOT_FOUND。
- 修法：`next.config.ts` 改为 `path.join(process.cwd(), "cache-handler.js")` 绝对路径（`formatDynamicImportPath`
  对绝对路径直接放行，两处指向同一文件）。
- `Dockerfile` 运行阶段补 `COPY --from=build /app/cache-handler.js ./cache-handler.js` —— 它不在 `.next` 里，
  不会被自动带上。
- 验证：`next/dist/server/config` 的 default(phase, cwd) 加载后 cacheHandler 为绝对路径、存在且可 import；
  不配 `REDIS_URL` 时仍为 `undefined` + 50MB 内存缓存（行为未变）。
