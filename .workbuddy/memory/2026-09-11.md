## 图片查看器：缩小时无法拖动（已修复并提交）
- 根因：`src/components/ui/ImageViewer.tsx` 平移判定用 `zoomRef.current > 1` 当「内容溢出」的代理条件，缩小时鼠标拖动直接落入 `ignored`；且缩放/旋转变化都不重新夹取位移，放大拖动后再缩回会停在偏移位置且拖不动。
- 修复：新增 `panBounds / clampOffset / canPan`，以图片原始布局框（`offsetWidth/Height`，不受 transform 影响）为基准算可平移空间；鼠标/笔只要有空间即可拖动，触摸在非放大态保留滑动切图；`applyZoom`/`rotateBy` 后重新夹取位移；拖动位移超过 3px 才抑制 click，保留「点黑色背景关闭」。
- 坑：react-hooks v7 的 immutability 规则禁止在 useCallback/useEffect 里写 `useRef.current`（useLayoutEffect 内允许），旋转改为直接读 `rotation` state，删掉了 rotRef。
- 状态：tsc + eslint 通过；浏览器交互复验由用户在本地自测。

## OneDrive 附件下载名丢失（已修复）
- 根因：附件落盘路径由 `cloudRelKey(ext)` 生成 `YYYYMM/{uuid}.{ext}`，原名只在 `Media.fileName` 里；而下载 `/api/dl` 对 OneDrive 直接 302 到 Graph 预鉴权链接，`Content-Disposition` 由 SharePoint 取**云盘存储名**生成 → 用户保存到本地的是 uuid 名，`n` 参数对 302 分支无效。
- 技术约束（已查证）：302 直连下无法指定下载名 —— `download.aspx` 只有 `download=1`（强制下载 vs 打开）这类布尔参数，`SourceUrl=` 只认真实文件路径。要让下载名 100% 保真就必须让字节经过服务端，而 Vercel 函数时长/带宽扛不住 200MB~250GiB 附件。结论：**存储名必须保留原名**。
- 定案（用户拍板）：落盘名 = `[rootPath/]YYYYMM/{安全化原名}_{uuid}{ext}`。原名在前（云盘可读、下载即原名），uuid 后缀保证全局唯一 → 无需探测重名、无并发覆盖；截断只作用于原名主体，uuid 与扩展名完整保留。
- `src/lib/storage/onedrive.ts`：新增 `sanitizeCloudName`（非法字符 `" * : < > ? / \ |` 与控制字符、首尾点空格、超长截断；保留名 CON/PRN/AUX/NUL/COM0-9/LPT0-9、`~$`、`_vti_`、`.lock` 均加下划线规避）与 `cloudItemPathFor`（同步纯函数）；取代此前的异步探测版 `resolveCloudItemPath`。
- 去重：session 与 legacy 两条上传路由新增查询 —— 同 `uploaderId + kind=ATTACHMENT + fileName + size + READY` 命中则直接返回已完成记录（`{ok:true, deduped:true, url, name, size}`），跳过整轮 Graph 上传；浏览器直传场景服务端不接触字节，无法算内容 hash，故以「同名同大小」为同一文件判据。客户端 `upload-attachment-client.ts` 识别 `deduped` 分支。
- `src/app/od/[driveId]/[...key]/route.ts`：原 `SEG` 只允许 `[A-Za-z0-9._-]`，会把中文/空格/括号原名直接 400；放宽为「非空、≤120 字符、非 . / ..、不含路径分隔与控制字符」。
- 验证：`_test/cloud-name.ts` 20+ 用例（中英文/非法字符/保留名/超长/点分日期/tar.gz/200 次同名唯一性）全通过；真实请求 od 网关对中文、空格、括号、`#`、`%`、原名_uuid 六类路径均返回 404（通过校验并查盘），修复前为 400；tsc + 全部改动文件 eslint 干净。
- 遗留：完整上传+下载 E2E 需真实 OneDrive 凭据，由用户自测。
