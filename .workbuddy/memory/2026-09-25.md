## 邮件模板链接带端口（本次修复）
- **根因**：`src/lib/request-origin.ts` 的 `requestSiteUrl()` 采信 `x-forwarded-port` —— 反代/容器往这个头里写的常是**上游内部端口**（`X-Forwarded-Port: 3000`）；`e0437ef` 先剥掉 host 的端口、又从这个头补回，等于把内部端口装回邮件链接（收件人打开必 `ERR_CONNECTION_REFUSED`）。
- **修法**：把判定抽成纯函数 `originFromHeaders()`；**经代理的公网主机一律不带端口**（判据 = 任一转接头出现即视为经代理，含 `x-forwarded-for` / `x-real-ip`），
  两个例外保留端口：**回环主机**（localhost / 127.* / 0.0.0.0 / [::1]，否则本地 dev 的预览链接点不开）与**零转发头的直连**（host 就是用户地址栏，端口是他自己敲的）；
  私网地址也不带端口；顺带兜住无中括号 IPv6 字面量（`::1` 会被端口正则啃掉尾巴 → 回退 env 基址）。
- **验证**：临时探针 `prisma/_origin-probe.ts` 15 条全绿，其中 8 条与旧实现结论不同（同类输入旧逻辑确实产出 `:3000`）＝断言有区分度；探针已 `copyFileSync` 到 `%TEMP%\pixelhub-bak-origin-probe.ts` 后从仓库删除。改动文件 tsc / eslint 0 错。
- 环境备注：本机 `node_modules` 缺 `@prisma/client` 生成产物（`prisma generate` 修）与 `pinyin-pro`（装过后又被一次 npm 操作 prune 掉）⇒ tsc 残留 `slug.ts` 的 TS2307，与本次改动无关。
