## 修复：多图上传失败（Chevereto 单文件约束）

根因：Chevereto V4 `/api/1/upload` 一次请求仅接受单个文件（文档约束）。代码中有两处违背/放大该约束，导致多图时只有首张成功：

1. `src/lib/actions/social.ts`（评论附图）：`Promise.all` 并发调用 `saveCommentImage`，多张图同时打 Chevereto → 仅首张成功。改为 `for...of` 逐张串行上传。
2. `src/components/upload/UploadWizard.tsx` 与 `src/components/admin/ResourceEditForm.tsx`（发布向导/编辑改稿，后台 `/admin/content/[id]/edit` 复用后者）：一次 FormData 打包多文件 POST `/api/upload`，单请求内串行 N×3 次 Chevereto 远端写入，易超时/中途失败连带后续。改为逐文件独立请求（单文件/请求），单张失败隔离、报错到具体文件；并按剩余容量截断选取量，顺带修复"一次选超上限整体 400"的体验问题。

配套：`src/app/api/upload/route.ts` 上传限流 30 次/h → 120 次/h（前端改为逐张请求后按请求计费会随张数倍增，按张放宽配额，注释说明）。

## GitHub 登录 redirect_uri mismatch + 邮件域名 CDN 兼容修复
- 病根：站点"公开域名识别"失准。①.env 第 18 行注释错误引导登记 `/api/auth/bind/github/callback`，该路由代码里不存在——绑定本就复用登录回调 `/api/auth/callback/github`（connections.ts 已注释：绑定=已登录再走 OAuth 自动 linkAccount）；GitHub App 只能登记一个 callback，登记错路径必 mismatch。②Auth.js 无 trustHost 也无 AUTH_URL，生产自托管+CDN 下 baseUrl 推导失真。③邮件链接/host 全走 siteUrl()（只读 env，缺省 localhost）。
- 修复（全部请求域名动态化，不写死 .env）：auth.config.ts 加 `trustHost: true`（从 host/x-forwarded-* 推导 baseUrl）；新建 `src/lib/request-origin.ts` 导出 `requestSiteUrl()`（headers 取 x-forwarded-proto/x-forwarded-host，逗号取首项，非请求上下文回退 siteUrl）；password-reset.ts 与 mail-notify.ts 链接改 `await requestSiteUrl()`；mail-template.ts 页眉 host 优先取 linkUrl 的 host（无链接回退 env）。.env 注释改为登记 `https://<域名>/api/auth/callback/github`（登录绑定共用）。
- 未动：SEO metadataBase/JSON-LD/sitemap/robots 仍用 siteUrl()（env 静态基址设计用途，动态化会让 layout 强制动态渲染，需另议）；mailer.ts 发件人 from 兜底域名未动（SMTP 认证域为准）；register-code.ts 无链接不改。
- 验证：tsc exit 0、eslint 0 error。用户侧待办：GitHub App 登记值核对为 https://公网域名/api/auth/callback/github。
- 补充：requestSiteUrl 协议【跟随转发头实际值】不假定 https（用户站点 http/https 并存）。nginx 侧：若 nginx 即协议边界（无 CDN / CDN 保持协议回源），X-Forwarded-Proto $scheme 本就正确；仅当 CDN 先终结 TLS 且回源 http 时需透传 CDN 的 x-forwarded-proto（map $http_x_forwarded_proto 优先、空回退 $scheme）。GitHub OAuth 回调平台侧强制 https，需以 https 访问站点。
