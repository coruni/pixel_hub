## 修复 GAME 详情页「游戏下载 + 版本历史」重复 & `vv` 前缀
### 重复的根因（重要，别再改错方向）
- 表面上像「两个区块渲染了同一批 URL」，实际是 **`ResourceVersion` 表在 GAME 上承担的是「下载源清单的存储」**，不是版本历史：

  - `_resource-edit.ts` 改稿时按 **url 做身份**增删同步这张表（保留 downloadCount / createdAt，改名不清下载数）。
  - `ResourceEditForm.tsx` 用 `resource.versions` 反推 `GameSection` 的 `downloads` 清单。

- **踩过的坑**：一度想把「发布时只建主源一条」当作修法，那会直接破坏改稿同步（改稿依赖每条源一条记录），已回滚。动这张表前先读 `_resource-edit.ts` 的同步逻辑。

## 修复「上传完抽屉不显示刚上传的内容」
- 根因两处，都在旧的 `if (!drawerHeldRef.current) setDraft(row)`：
  1. 抽屉**关着**时无条件 `setDraft(row)` —— 用户之前开的草稿（填了一半的标题、选的外链模式）被整个顶掉。
  2. 抽屉**开着**时完全不动作 —— `drawerHeldRef` 为 true，抽屉里还是空文件占位，用户看到「传完了」却看不到文件。
- 新增 `applyUpload(row)` 按当前抽屉状态分流（抽屉状态**由落行也由它负责**，调用方不要先 `setRows`，否则重复行）：
  | 抽屉状态 | 行为 |
  |---|---|
  | 关着 | 落一行 + 新开草稿指向它 |
  | 开着新增草稿，kind=file | 只把文件补进草稿，保留用户已填的标题/大小；**不落行**，等点「添加」 |
  | 开着新增草稿，kind=link | 落一行 + 另起草稿（一行只能一个来源，不把文件塞进外链） |
  | 开着编辑既有 file 行 | 落一行 + `patch(open)` 就地更新该行 |
  | 开着编辑既有 link 行 | 落一行 + 另起草稿，不覆盖外链 |
  | 清单已满 20 条 | 提示「附件已达 20 条上限，新上传的文件未加入清单」，不静默吞 |
- **`drawerHeldRef` 换成 `viewRef`**（`{ draft, open, kinds }`）：`applyUpload` 在 `await` 之后才跑，原 ref 只存了个布尔，不够做 `kind` 判断——需要读的是「此刻」的 kind 与下标，不是闭包捕获那一刻的。用 `useEffect` 同步。
- 已知行为：批量上传且抽屉关着时，每个文件各调一次 `applyUpload`，最终只有最后一个的草稿留下（一行只能编辑一条）；前面的都已在清单里，仍可从齿轮图标打开编辑。这是设计而非 bug。
- 验证：`tsc --noEmit` exit 0；eslint（upload 目录 + version.tsx + ResourceEditForm.tsx）exit 0。

## 单文件字节进度（percent）
- 根因：`uploadAttachment(file, onProgress)` **本来就支持**字节回调（OneDrive 分片直传按已完成分片累计 0..100），是 `postAttachment` 没把第二个参数透出去，白丢了一条现成能力。
- `wizard-sections.tsx`：`postAttachment(file, onProgress?)` 转发到 `uploadAttachment`；新增 `percent` state（**单值就够**——上传是串行的，任一时刻只有一个「当前文件」，不用按文件建表）；`onFiles` 循环里每个文件开传前 `setPercent(0)`、完成/失败后 `setPercent(null)`。
- `AttachmentUpload.tsx` 新增 `percent?: number | null`：细条 + 百分比数字，数字是给屏幕阅读器和看不清条的人兜底的（`role="progressbar"` + aria-value*）。
  - **`percent === 0` 不渲染**：刚起步条里没内容，显示出来反而像卡住；`> 0` 才出现。
  - dropzone 里进度条插在文案与规格提示之间；button 变体里进度条用 `min-w-24 flex-1` 占满剩余宽度（行内按钮旁边单摆一条 0 宽度的条没意义），容器补 `min-w-0`。
  - 进度条用 `<span>` 而非 `<div>`：dropzone 的父节点是 `<label>`，label 里放块级 div 会破 HTML 内容模型。
- 外层投放区与抽屉内投放区都接 `percent`，两条入口显示同一份进度。
- 已知限制：**回退到普通 API（无云盘 / `NO_CLOUD`）的分支拿不到字节回调**，只在完成时收到一次 100——进度条会「不动然后满」。要真实进度得给 `postLegacyAttachment` 换 XHR 的 `upload.onprogress`，本次未做。
- 验证：`tsc --noEmit` exit 0；eslint（upload 目录 + version.tsx + ResourceEditForm.tsx）exit 0。
