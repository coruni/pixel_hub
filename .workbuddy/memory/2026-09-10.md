## 诊断：Bing「已知但无法索引」≠ NSFW 问题（线上实测）
- 用户收到 Bing URL 检查提示「The inspected URL is known to Bing but has some issues which are preventing indexation」（含中文译文），怀疑是 NSFW 导致。
- 结论：该文案是 Bing 的**通用「已发现但拒绝收录」**措辞（官方 Q&A 确认对应 noindex / 状态码异常 / JS 依赖 / 低权重 / 薄或重复内容 / sitemap 问题 / soft 404），**不是成人内容分类通知**。判定分支：若因 noindex 则 Bing 明说「Excluded by 'noindex' tag」；若 robots.txt 拦截则明说「Blocked by robots.txt」；两者都会指名道姓，不会用这句通用话术。
- 线上实测（Bingbot UA，https://www.poixel.top，openresty 前置）：
  - SFW 详情页 → **200** + `<link rel=canonical>` 指向自身 www 域名 + **无 robots meta** + 正文完整（73KB，含 md-body）→ 技术面干净可收录。
  - NSFW 详情页（匿名）→ **404** + Next 对 notFound 自动注入的 `<meta name="robots" content="noindex">`（注意是 noindex 而非我们 generateMetadata 里的 noindex,nofollow——说明 404 分支的 metadata 由 notFound 接管）→ 按 D9 设计对爬虫完全不可见。
  - 不存在的 slug → 404，正常。
  - robots.txt → 正确 `Sitemap: https://www.poixel.top/sitemap.xml`（生产环境 SITE_URL 已配；本地 .env 无 SITE_URL/AUTH_URL，故本地会回退 localhost）。
- 关键事实：已发布 144 条，其中 **NSFW 59 条（41%）**；`queries.ts:223 if (!allowNsfw) where.nsfw = false` 保证未登录列表不含 NSFW，sitemap 也只列 SFW → NSFW 页既不被内链也不被 sitemap 暴露，对爬虫只表现为 404。故 NSFW 不是这条提示的来源（除非 Bing 历史已收录过某些 NSFW URL）。
- 本次发现并修掉的真实缺陷（commit 待定）：`src/app/sitemap.ts` 仍列 `${base}/search`，而 /search 已由 next.config redirects **308/301 跳 /browse** → sitemap 含跳转 URL，Bing 报「URL redirects」并浪费抓取配额。已删除该条并加注释。tsc 0 / eslint 0 / diff-check 0。
- 未修、待用户决定的线上问题（在 nginx/openresty，不在仓库）：
  1. **`https://poixel.top` → 302 → `https://www.poixel.top`**，裸域跳转用了 302（应为 **301**）；`http://www.poixel.top` → 301 是对的。302 属「临时」，Bing 可能长期把裸域当规范域，是 host 规范化隐患。
  2. 全站响应 `Cache-Control: private, must-revalidate, no-cache, no-store, max-age=0`（页面读 `auth()` 会话导致动态渲染），爬虫无缓存且被标记为个性化页面。
  3. `/browse` 无 q 时所有 `?cat=`/`?page=` 变体共用同一 title「浏览 · Pixel Hub」且**无 description**（仅 canonical 区分）→ 分类页近重复，是「爬取但不收录」的典型诱因；建议按 cat 输出独立 title/description。
