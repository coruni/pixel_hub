# 2026-09-19

## 修复音乐 / 视频上传（选不到文件 + 没有进度条）

- **用户报**：「修复 视频 和音乐 上传 以及无法上传问题」。

- **根因 1 —— 选不到文件（这是「无法上传」的主因）**

  `AttachmentUpload` 的 `<input accept>` 写死 `attachmentAcceptAttr(limits.attachmentExts)`（后台 `/admin/uploads` 的「附件后缀表」），而 MUSIC / VIDEO 的服务端白名单是 `avExtsFor(kind)`（`src/lib/av.ts`）。两套表**不等价**：

  | 种类 | 服务端允许（`avExtsFor`） | 附件表默认覆盖（`DEFAULT_ATTACH_EXTS`） |
  |---|---|---|
  | 音频 | mp3, m4a, aac, wav, flac, ogg, oga, opus | mp3, wav, ogg, flac → **m4a / aac / opus / oga 选不到** |
  | 视频 | mp4, m4v, webm, mov, mkv, ogv | mp4, webm, mkv → **m4v / mov / ogv 选不到** |

  更糟的是：只要管理员在后台把附件后缀改窄（比如只留压缩包/文档），音乐/视频就**完全选不到文件** —— 而 `hint` 还照着 `avExtsSample(kind)` 显示「仅 mp3/m4a/aac/…」，文案与行为直接矛盾。

  旁证：`av.ts` 的 `avAcceptAttr(kind)`（`audio/*,.m4a,.flac,.opus` / `video/*,.mkv`）**早就写好了，全站零调用** —— 接线漏了。已核对它覆盖 `avExtsFor` 的全部后缀。

- **根因 2 —— 没有进度条**

  `av-section.tsx` 传 `progress={{ done: progress, total: 100 }}`。`progress` 的语义是「批量：第 n / 共 m 个文件」，于是被渲染成「上传中 45/100…」（把百分比当文件序号）；真正的单文件字节进度参数 `percent` 从没传过 → 音视频上传全程没有进度反馈，看起来像卡死。

- **改法**

  | 文件 | 改动 |
  |---|---|
  | `src/components/upload/AttachmentUpload.tsx` | 新增 `accept?: string` prop，默认 `attachmentAcceptAttr(limits.attachmentExts)`（其余调用点行为不变）；内部 `const acceptAttr = accept ?? …`，input 用 `acceptAttr` |
  | `src/components/upload/av-section.tsx` | 传 `accept={avAcceptAttr(avKind)}`；`progress={{done,total:100}}` → `percent={progress}` |

  其余三处 `AttachmentUpload` 调用点（`version.tsx`、`wizard-sections.tsx` × 2）走默认，不受影响。`AvSection` 被 `UploadWizard` 与 `ResourceEditForm` 共用 → 发布向导与后台改稿一起生效。

- 验证：`tsc --noEmit` exit 0、eslint（resource/detail + social + upload + lib/ui）exit 0。

- **未改（属配置，不是 bug）**：音视频上限沿用 `attachmentMaxMb`（默认 200MB，后台可调到 OneDrive 单文件 250GiB）；上传限流 10 次/小时（attachment 与 av 各一条 key），大文件反复重试会撞 429「上传过于频繁」。
