**追加（13:26）**：落实对照图里的「拖拽上传」。评论输入区接上站内现有 hook。
- `Comments.tsx` 引入 `useFileDrop` / `useFilePaste`（`src/lib/hooks/`，全站上传入口复用同一对），
  挂在整个输入区容器（`relative mt-4`）上，而不是只挂附图按钮——拖到编辑器上、缩略图上、
  按钮上任意位置都算数，与 media-picker.tsx 的做法一致。
- 拖拽态：整块盖一层 `border-2 border-dashed border-brand-500 bg-brand-50/95` +
  「松开即可添加附图」。**必须 pointer-events-none**，否则遮罩自己会触发新的 dragenter/dragleave
  把深度计数器搅乱。像素站点不用毛玻璃。
- disabled 条件：`sending || imagesFull`（imagesFull = imageMax<=0 或已达上限），
  与 input 的 disabled 语义对齐——满额时拖进来的图会被 slice 静默丢弃，不如不接管。
- 附图入口文案补「拖入或粘贴也可添加」；拖拽时按钮边框同步转 brand-500。
- 顺带给 `pickImages` 加了 `list.length === 0` 早退（useFilePaste 在剪贴板无图时本来就不调用，
  但 useFileDrop 的 onDrop 有可能拿到空 FileList）。

**追加（13:38）**：用户纠正附图区布局。原实现把「附图 0/4」按钮 + 飘在旁边的
「拖入或粘贴也可添加」文案 + 缩略图全塞在一行 flex 里，视觉杂乱。
改为（对齐 media-picker.tsx 的虚线格形态）：
- **无图**：只渲染一个「附图 0/4」入口按钮，其余不出现。
- **有图**：上面仍是入口按钮（显示计数），下面另起一行渲染缩略图 80×80 +
  一个 80×80 虚线「＋ 添加 / 拖入或粘贴」方框，提示文案**收进方框内**，不再飘在外面。
- 添加方框与入口按钮**共用同一个 input**：给 input 加 `id="comment-image-input"`，
  方框用 `htmlFor` 关联（一个 input 不能在两处渲染，只能这样复用）。
- 缩略图从 56→80（h-20 w-20），与方框同尺寸对齐。
- `imagesFull` 时方框不渲染，与 useFileDrop/useFilePaste 的 disabled 条件保持同步，
  避免「框还在但拖进去没反应」。拖拽态文案在方框内变「松开即可」。
